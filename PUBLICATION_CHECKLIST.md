# Before Making the Repository Public

- [ ] Choose and add a source-code license.
- [ ] Add the final paper title, authors, venue, and DOI to `CITATION.cff`.
- [ ] Confirm that the miniF2F-derived data may be redistributed under the
      upstream terms.
- [ ] Revoke any API key that has previously appeared in a chat, terminal log,
      issue, or commit.
- [ ] Review `git status` and confirm that `.env`, `.runs`, and `.datasets` are
      not tracked.
- [ ] Create the GitHub repository and push the `main` branch.
- [ ] Add a release or tag identifying the paper implementation.
- [ ] If separate-memory results are later generated, publish them under a new
      tag and do not replace the historical paper results.
